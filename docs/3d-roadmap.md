# 3D-карта города: что делать дальше

Документ для того, кто берёт на себя визуализацию. Здесь состояние на сейчас,
границы ответственности и задачи по убыванию ценности.

## Что уже есть

Карта — [`components/city/city-map.tsx`](../components/city/city-map.tsx), клиентский
компонент, который монтируется через `dynamic(..., { ssr: false })` из
`components/sim/simulator.tsx`. Загрузка и инстансинг GLB вынесены в
[`components/city/model-instances.tsx`](../components/city/model-instances.tsx).

- Пять кварталов по условной схеме города (`PLOTS`), размещение процедурное:
  `buildingsFor()` раскладывает три варианта жилых GLB по сетке, высота зависит от
  оценки района. Выбор модели, поворот и разброс детерминированные (`jitter()`
  от синуса — одинаковая картинка при каждом рендере, никакого `Math.random`).
- Цвет района — `scoreColor()`: 45 и ниже красный, 65 и выше зелёный.
- Принятые меры превращаются в предметы на земле: `propsFor()` раскидывает их
  по районам, вид предмета выбирается по направлению меры (`PROP_BY_DIRECTION`).
  Городские меры рассыпаются по всем пяти районам, районные — только в своём.
- Две камеры: орбита и вид сверху. Экспорт кадра в PNG.
- Четыре постоянных ориентира: Байтерек, Хан Шатыр, Дворец мира и согласия,
  Нур Алем. Кнопки под картой и подписи над моделями приближают камеру;
  «Весь город» возвращает обзор. Перелёт длится 0,6 с, отменяется ручным
  управлением и учитывает `prefers-reduced-motion`.
- Диорама с площадями, бульваром, условным руслом Есиля и двумя мостами.
  Застройка и предметы мер не занимают площади памятников. Планировка условная,
  памятники и постоянные парковые деревья не меняют оценку района.
- Подписи районов и ориентиров — единый DOM-слой с проекцией координат камеры
  ([`city-labels.tsx`](../components/city/city-labels.tsx)). Наследуют локальный
  шрифт страницы, не требуют сетевых шрифтов или отдельных React-корней.
  При приближении подписи не раздуваются; видна только выбранная достопримечательность.
- Первый комплект локальных моделей: три жилых здания, дерево, остановка,
  общественный корпус, фонарь и люк. Исходный генератор Blender, превью и
  описание контракта находятся в [`public/models/`](../public/models/README.md).
  Отдельный генератор добавляет четыре узнаваемых ориентира столицы.
  Во время загрузки и при ошибке отдельного GLB показываются прежние примитивы;
  подложка, подписи и остальные модели остаются видимыми.

## Границы: что можно трогать, а что нет

**Твоя зона:** `components/city/**`, `public/models/**`, этот файл.

**Не трогай без согласования:** `lib/engine/**` (движок расчёта, покрыт тестами,
от него зависят эталонные значения из ТЗ), `lib/ai/**`, `lib/domain/**`,
`components/sim/**`. Единственная строка в чужой зоне, которая тебе может
понадобиться, — монтирование `<CityMap>` в `simulator.tsx`.

Так мы не столкнёмся в merge: мы работаем в разных папках.

## Контракт данных

`CityMap` получает ровно два пропса, оба уже посчитаны движком:

```ts
breakdown: ScenarioBreakdown   // lib/engine/score.ts
decisions: Decision[]          // lib/domain/city.ts
```

Из `breakdown` тебе интересны:

| Поле | Что в нём |
|---|---|
| `districts[]` | `id`, `name`, `before`, `after`, `delta`, `isWeakest`, `population`, `profile` |
| `districts[].indicators[]` | десять показателей: `key`, `label`, `before`, `after`, `delta`, `critical` |
| `event` | сработавший стресс-тест: `name`, `description`, `impact` (отрицательный) |
| `weakest` | слабейший район — тот, что тянет 30% итогового балла |

Ничего не пересчитывай сам: если нужна величина, которой нет в `ScenarioBreakdown`,
скажи — добавим в движок и покроем тестом.

## Задачи по убыванию ценности

### 1. Реакция на стресс-тест

Сейчас событие меняет только цифры, карта на него не реагирует никак. Это самое
заметное упущение: в `breakdown.event` уже лежит и название, и то, во сколько баллов
оно обошлось. Сделать: район, по которому ударило событие, затемняется и получает
видимый маркер (дым над кварталом, красная штриховка подложки, пульсация). Для
общегородских событий — эффект по всем пяти.

Границы: событие может быть `scope: "city"` или `"district"`, см. `lib/domain/events.ts`.

### 2. Плавный переход при смене сценария

Сейчас застройка перестраивается мгновенно. Интерполяция высот за 300–400 мс сделает
причинно-следственную связь «поставил меру → район подрос» наглядной.

**Важно:** канвас стоит на `frameloop="demand"` — кадры рисуются только по запросу.
Для анимации нужен `useFrame` плюс `invalidate()` из `useThree()`, иначе движение
не отрисуется. Не переключай весь канвас на `frameloop="always"` ради анимации:
страница начнёт греть процессор постоянно.

### 3. Клик по району

Клик по кварталу → подсветка и карточка с десятью показателями этого района
(данные уже есть в `districts[].indicators`). Дублирует таблицу внизу, но на карте
это читается быстрее.

### 4. Прогулка от первого лица

Камера от лица горожанина: WASD плюс мышь через `PointerLockControls` из drei.
Рабочая реализация такого контроллера есть в соседнем проекте
`Dev/join-way/grand-market` → `components/projects/project-3d-scene.tsx`, компонент
`CameraRig`. Оттуда стоит взять:

- набор клавиш через `useRef(new Set<string>())` по `event.code`;
- `preventDefault()` на стрелках, пока курсор захвачен, иначе страница скроллится;
- сброс нажатых клавиш на `window blur` и `pointerlockchange` — иначе камера
  уезжает вечно, если клавишу отпустили вне окна;
- коллизии как плоский список прямоугольников: препятствие, внутри которого ты уже
  находишься, перестаёт быть твёрдым, иначе можно застрять намертво;
- скольжение вдоль стены: пробуем `(x, z)`, потом `(x, старый z)`, потом `(старый x, z)`;
- клампинг `delta` (`Math.min(delta, 0.05)`), иначе после просадки кадра пролетаешь
  сквозь препятствие.

Режим прогулки — единственный случай, когда `frameloop` должен стать `"always"`.

### 5. Настоящие модели вместо примитивов

Комплект из двенадцати GLB подключён. Файлы лежат в `public/models/`, каждый содержит
один меш с одним непрозрачным материалом и цветами вершин. Текстур, анимаций и
сетевых декодеров нет; `useGLTF` вызывается с отключёнными Draco и Meshopt.
Модели предметов загружаются после появления соответствующей меры; дерево также
используется в постоянном озеленении набережной.

На каждую группу модели приходится один `InstancedMesh`: максимум тринадцать
вызовов отрисовки моделей за проход (деревья парка и мер — две отдельные группы),
независимо от количества копий. Подложка, дороги, площади и мосты рисуются отдельно. Матрицы,
цвета и границы обновляются при изменении размещений, без постоянного `useFrame`.
Изменение количества экземпляров пересоздаёт их буфер, сохраняя геометрию и
материал из кэша. Цвет жилой застройки умножается на уже рассчитанный цвет района.

Генераторы [`generate_city_kit.py`](../public/models/source/generate_city_kit.py) и
[`generate_landmarks.py`](../public/models/source/generate_landmarks.py)
не зависят от соседнего проекта. Инструкции, габариты,
состав и бюджет описаны в [паспорте комплекта](../public/models/README.md).
GLB имеют основание на Y=0 и центр по X/Z; жилые модели нормализованы по высоте
до 1, чтобы масштаб из карты продолжал отражать оценку района.

Дальше можно уточнять силуэты и добавлять новые городские здания. Общий
бюджет остаётся не больше 2–3 МБ; для новых моделей обязательны инстансинг,
локальные ресурсы и проверка контракта генератором.

### 6. Композиция города

Река, мосты, набережная и четыре знаковых здания уже есть в
[`landmarks.tsx`](../components/city/landmarks.tsx). Базовая схема остаётся условной,
не географической картой. Следующий шаг — разная плотность и типология застройки
по районам: Есиль просторный, Алматы плотный старый. Профили районов лежат в
`districts[].profile`, их можно читать как подсказку.

## Правила, которые нельзя нарушить

- **`preserveDrawingBuffer: true`** на канвасе — без него `toDataURL` вернёт пустую
  картинку и экспорт кадра сломается.
- **Никаких шрифтов и ассетов из сети** — проект должен работать без интернета
  после `pnpm install`.
- **Никакого `Math.random`** в геометрии: картинка должна быть одинаковой при каждом
  рендере, иначе застройка будет прыгать на каждый чих состояния.
- **`pnpm lint`, `pnpm test`, `pnpm build` должны проходить** — их гоняет CI на каждый
  пуш и pull request.
